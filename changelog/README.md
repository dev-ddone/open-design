# Changelog directory

Every release has one Markdown file named with its semantic version. Entries describe user-visible behavior, migrations, validation and known limitations. `UNRELEASED.md` is the only place for work not yet assigned to a version.

Release files must contain:

1. scope;
2. added, changed and fixed items;
3. database or deployment changes;
4. validation performed;
5. known limitations and compatibility notes.
