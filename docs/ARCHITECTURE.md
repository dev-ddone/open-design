# Architecture

## Request flow

```text
Browser
  ├─ HTTPS ────────────────> Hono HTTP API
  └─ authenticated WSS ───> Yjs collaboration server
                                  │
                    ┌─────────────┴─────────────┐
                    │                           │
                PostgreSQL                 MinIO / S3
          users, tenants, designs,       uploaded image and
          metadata and Yjs state          SVG object bytes
```

## Trust boundaries

- The signed HTTP-only cookie identifies the user.
- `X-Organization-ID` selects a workspace but never grants access by itself.
- Organization membership is resolved from PostgreSQL for every protected request.
- Role middleware protects writes.
- Design access is independently checked before WebSocket upgrade.
- Object storage keys are generated by the server and never accepted directly from clients.

## Frontend boundaries

- `session.tsx`: identity and selected organization.
- `api.ts`: authenticated requests and organization header.
- `use-designs.ts`: design/page persistence and selected-client behavior.
- `use-collaboration.ts`: Yjs/Fabric synchronization and awareness.
- `elements-library.tsx`: unified visual element discovery and insertion.

## Server boundaries

- `config.ts`: validated environment configuration.
- `db.ts`: PostgreSQL, transactions and migrations.
- `auth.ts`: sessions, organizations and role checks.
- `storage.ts`: local or S3-compatible object storage.
- `elements.ts`: curated elements and Iconify provider.
- `collaboration.ts`: WebSocket authentication and persistent Yjs documents.
- `index.ts`: HTTP API and production static application.
